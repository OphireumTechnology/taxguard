## 2. Implemented

### Cycle 1 — emergency stop for a model, tool or workflow stage (Phase 5)

- **Verification before building:** every actual execution path already enforces all five stop scopes, as existing tests prove.
  - Gateway: before dispatch, after durable admission, mid-transport (a provider response is discarded), and before retry.
  - Capability executor: admission and continuation.
  - A00 orchestrator: mid-operation.
  - Human-review service.

  The gap was that operators could engage only GLOBAL and AGENT stops.
- **`KillSwitchService`:** adds MODEL (`model_id` + `model_version`), TOOL (`tool_id`) and WORKFLOW (`workflow_stage` 1–18) activation.
  - Targets must exist in `ai_models`, `ai_tools` or `ai_workflow_stages`; otherwise `AI_KILL_SWITCH_UNKNOWN_TARGET` (400) and nothing is written.
  - WORKFLOW is pinned to `LEGACY_18_V1`, and a client-supplied `workflow_version` is rejected, preserving H10.
  - Column layout matches the table's CHECK constraint.
- **UI:** "One model version / One tool / One workflow stage" options with persisted stage names; the confirmation names the exact target. Deactivation is still absent (H11).

### Cycle 2 — accurate stop display in the Control Center

- The registry view now marks an agent stopped when its configured model is stopped, with `stop_reason` GLOBAL / AGENT / MODEL.
- It returns `scoped_stops` for MODEL, TOOL and WORKFLOW.
- The panel shows a "Scoped emergency stops in force" banner and a "Stopped by" column. Previously, a model stop would have left affected agents shown as "Not stopped".

### Cycle 3 — account suspension and session revocation (Phase 1), with a defect fix

- **New regression tests** for `SupabaseDurableSessions.verify` against an in-memory query-builder stand-in (synthetic rows). The same token is rejected immediately after:
  - suspension, revocation, pending or disabled membership;
  - server-side `revoke()`;
  - expiry;
  - a tenant mismatch;
  - membership removal;
  - identity removal.

  The tests also show that the server-recorded role overrides any role stored in profile data, and that malformed tokens are rejected.
- **Defect found and fixed:** outside production, after one successful `verify()`, the user was cached in `db.users`, and later calls synthesized an `active` membership from that cache even when the database authoritatively returned *no membership row*. Removing a member therefore did not revoke their live session in development or in any staging without `NODE_ENV=production`. Local fallbacks now apply only when the database read **errors**; production behaviour is unchanged.
