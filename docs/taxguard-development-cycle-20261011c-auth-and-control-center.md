## 3. Incident: encoding corruption introduced and repaired this session

Several files edited in cycles b and c were rewritten with Windows PowerShell 5.1 `Get-Content -Raw` / `Set-Content -Encoding utf8`. This decoded UTF-8 as cp1252 and added BOMs, so `—`, `…` and `→` became mojibake, including visible UI text in `PracticeAdminWorkspace.tsx`, `AiEmergencyStopPanel.tsx`, `AiControlCenterPanel.tsx` and the requirements matrix. The checkpoint `.orig` copies made with `git show | Out-File` were also re-encoded.

**Repair:**

1. Each affected file was reversed (cp1252 → UTF-8) only where mojibake was present, with a check for replacement characters.
2. Files were rewritten as UTF-8 without a BOM, with line endings preserved.
3. The original BOM was restored on `ai-governance.routes.ts` and kept on `productionGovernance.ts`; both had BOMs in the index.
4. All checkpoint `.orig` files were regenerated byte-exactly from the index with `cmd /c "git show :path > file"`.

**Verification:** every modified file now has the same BOM state as its index version, and no modified or new file contains mojibake. The traceability JSON's mojibake came only from the corrupted matrix headings and was cleared by regeneration. A memory note was recorded to prevent recurrence.
